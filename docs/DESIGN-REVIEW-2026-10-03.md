# macOS design review — October 3, 2026

The current direction comes from the user’s repeated rejection of the earlier titlebar experiments and the prior Astra review recorded in `PAGE-REVIEW-2026-10-02.md`. The selected sidebar destination already identifies the page. The titlebar should identify only the workspace, immediately to the right of the sidebar. This pass follows that direction and extends the review to the overview, document presentation and navigation hierarchy. It does not claim a new independent Astra review.

The previous design gave equal weight to several bordered overview panels, repeated initialization status in both Readiness and Checks, repeated the execution location, and offered reinitialization in two places. The README also had a surrounding card and a page label competing with the document’s own heading. Source inspection supports these findings; no current screenshot was available because native inspection again failed with “Sky Computer Use native pipe closed before response.” Historical screenshot assessments remain in the earlier review rather than being presented as current evidence.

## Implemented direction

The overview now uses a leading reading column with 24-point page gutters and 24-point separation between plain sections. Dividers establish section boundaries. Status and the next available action come first, followed by the latest run, Git source and Terraform context. Detailed checks are available in a disclosure under Terraform. State counts accompany that context. The repeated execution text and secondary reinitialize action were removed; initialization and validation remain native toolbar actions. The next-action control uses a borderless text style, preserving its existing readiness and apply semantics without a glass or prominent capsule.

README content now sits directly on the document surface. A small file line provides the editor and refresh actions; the document retains its own typography and headings. The filename exposes its full path in help. It does not repeat a large page title or add a title band.

Sidebar counts are secondary, aligned to the trailing edge and use fixed-width numerals. Navigation labels keep their own leading alignment and no longer incorporate changing counts into their names. Environment inputs have a terminal symbol to distinguish them from Terraform variables. The status footer uses the same compact spacing as the sidebar. The existing native split view, sidebar visibility behavior and stable empty input lists are preserved.

The visible workspace title uses a standard left `NSTitlebarAccessoryViewController` with a plain, single-line `NSTextField`. Its position follows the actual sidebar edge, measured in window coordinates, rather than centering the native title or hard-coding the sidebar width. The real `NSWindow.title` remains the workspace name for window identity and accessibility, with its duplicate drawing hidden. The native sidebar button stays next to the window controls inside this accessory. Its accessible Hide/Show label and Command-Control-S equivalent are preserved. When the sidebar is hidden the title follows that button. The label tail-truncates, supplies the full name as help, and caps its width to leave room for page actions and search. The accessory has no custom material, background, capsule, header band or title separator.

The cross-page pass keeps selected resource, run and output identity inside their inspectors; those identities are useful and are distinct from repeating the selected page name. Resource and output inspectors share 20-point gutters and monospaced technical identifiers. Resource attributes retain aligned name/value columns when they fit and switch to name-above-value rows when the detail pane is narrow. The copy action remains next to its attribute. This affects layout only: the existing masked display values remain the source for rendering and copying.

Terraform and environment inputs now use monospaced names, six-point row padding and top-aligned actions. Type information gets its own bounded line; other metadata wraps as ordinary secondary text rather than compressing several independent labels. Required/missing filters use native checkboxes. Existing descriptions still wrap, and the empty input pages retain their mounted lists, preserving the user-verified sidebar repair. Resource, output, run and input collections use consistent inset lists and row spacing. Compact resource metadata wraps within the row. Output search now lives with its collection, like resource search, so it does not compete with workspace identity and page actions in the titlebar.

Run identity, status, date and captured branch/commit remain immediately visible. Secondary timing, trigger and source context move into a native Run details disclosure, giving the plan more space on the first screen. Plan action counts use an adaptive grid, and long change addresses wrap while operation labels retain their width. The operation filter no longer repeats its label beside the menu. Apply retains its original gating and behavior, with a semibold borderless control in place of the prominent capsule. No action has become automatic or gained a new shortcut.

Configuration removes the duplicate workspace heading from its file list and uses a sentence-case Files label. Wide editor headers show the selected relative path once, with the full path available as help and through Copy. At compact widths, file selection, modified status, Save, actions and Refresh share one existing functional row; the repeated second filename/action row is gone. The source editor, Find, Go to Line, draggable validation split and unsaved/external-change guards remain intact. Save and starter actions are native borderless controls. The starter preview uses a plain text surface instead of a rounded container.

Shared copy controls use a short visible Copy label with the full action-specific help and accessibility description. A standalone repository copy action retains an explicit visible subject. This avoids repeating long resource addresses, output names or diagnostic descriptions inside the action button while keeping their purpose available to assistive technology.

## Verification and acceptance

All twelve edited Swift sources pass syntax parsing, including the complete cross-page pass. The isolated AppKit titlebar implementation passes native Swift type checking against the installed SDK. Whitespace validation passes. The slice’s first full build attempt was blocked by normal compiler cache permissions; after escalation, it stopped at the concurrently added MCP package’s unresolved dependency lockfile. The parent integration build must supply the final application compilation evidence.

No rendered title placement, narrow-window action allocation, sidebar hide/show interaction, full-screen behavior, light/dark appearance, VoiceOver traversal or keyboard acceptance is claimed. In particular, the standard titlebar accessory’s allocation beside SwiftUI toolbar items must be observed at the 900-point minimum window width and with long folder names before accepting the design. Source-level alignment and successful type checking are not visual proof. Habitable-rt3.57 remains in progress for user design review; rt3.21 retains native interaction acceptance. The release, distribution and Homebrew tap hold remains in force.


The new HCP viewer follows the same native layout direction. Below 960 points of content width it uses compact workspace/run menus and full-width scrolling detail; wide content retains three draggable columns. Connection fields flex, actions occupy a separate row, and logs use plain document surfaces. Explicit selection bindings avoid duplicate API requests on model refresh or view remount. Search, pagination, remote identity and available links remain accessible in either layout. Syntax and whitespace checks pass; rendered compact/wide acceptance remains pending.


Parent integration verification now passes the optimized universal Xcode build for arm64 and x86_64, the universal app verifier, project-file validation and whitespace checks. The combined core suite executes 217 tests with two expected opt-in skips and zero failures. These checks supersede the slice’s earlier dependency-resolution blockage; they do not replace rendered design acceptance or lift the release hold.

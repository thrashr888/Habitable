# Habitable review — September 23, 2026

Scope: macOS UI, Terraform process execution, saved-plan lifecycle, workspace/state parsing, CLI version management, and the new run-history store. This is a code review plus local provider-free integration testing. Cloud backends and real provider credentials were not exercised. Beads is the source of truth for issue status.

## Highest-priority findings

| Priority | Beads issue | Finding and consequence | Required outcome |
| --- | --- | --- | --- |
| P1 | Habitable-px9 | Plan review consumes CLI event summaries, so before/after attributes and replacement reasons are unavailable before Apply. See `Runner.plan`, `StructuredLogView`, and `ResourceView`. | Inspect the same saved plan artifact with `terraform show -json` and display a sensitive-aware attribute diff. |
| P1 | Habitable-lfb | Variable/environment editors change arrays only. `Runner` receives no edited inputs; HCL parsing is line-based, and JSON variable parsing does not read the file bytes. | Clearly define saved inputs, validate them, and pass them into plan; until then, make the prototype nature explicit. |
| P1 | Habitable-hgw | `Workspace.validate` refreshes state only when a local `terraform.tfstate` file was found. Remote backends can reopen with empty Resources/Outputs. | Query the selected backend after validation, distinguishing empty state from inaccessible or failed state retrieval. |
| P1 | Habitable-45p | `transformShow` reads only `root_module.resources`; resources in `child_modules` disappear from the inventory and counts. | Recursively traverse module resources with stable full addresses and nested-module fixtures. |
| P1 | Habitable-2u2 | Locks are per window, and directory identity omits the selected Terraform workspace/backend. | P2 | Habitable-wkr | Commands buffer complete output and cannot be cancelled; a stalled command can leave the UI locked. | Stream bounded output and cancel the process tree while preserving diagnostics and reconciling state. |

## Addressed in the persistence change

Run construction no longer starts a command before its number and initial history record exist. Per-run atomic records preserve results without whole-history overwrites. Restored plans cannot Apply, and unfinished records show an unknown outcome instead of implying success or continuing execution. Run-to-workspace ownership no longer forms a retain cycle. History write errors remain visible and retryable. Structured output values marked sensitive are redacted before persistence, and the JSON parser no longer prints every raw event to the console.

The failed-apply path (`Habitable-z92`) now retires other pending plans and refreshes state, because a failed apply may have partially changed infrastructure. A regression test checks both history and in-memory results.

## 0.3.0 follow-up

The five P1 findings above are addressed in 0.3.0. Plans are inspected from the exact saved artifact before Apply, and the review shows changed attributes and replacement paths while respecting Terraform's sensitive and unknown markers. Explicitly saved editor inputs are validated and passed to plans; values found in workspace files or the process environment remain display-only. State loading queries the selected backend even without a local state file, child-module resources appear in the inventory, and a cross-process workspace lease prevents overlapping commands and rejects stale plans after context or state changes. Run history records the selected Terraform workspace and backend identity. The provider-free init check and Settings description alignment were also corrected.

The remaining execution risk is bounded output and cancellation (Habitable-wkr). App-level redaction of inputs marked sensitive in Habitable, beyond Terraform's own `sensitive = true` behavior, is tracked as Habitable-r6l. Recovery from a failed durable coordination write is tracked as Habitable-iq7. Beads remains the source of truth for these follow-ups.

The full 43-test suite passed with the real Terraform 1.16.4 CLI and official-release download enabled. The Xcode Debug build succeeded for arm64 and x86_64. Live UI checks showed the description editor starting at the leading edge, the Initialized check green after repeated init, and the saved-plan Review tab loading a no-change plan before Apply.
